# Revenue Nomad

Every open **fractional GTM** role. One board.

Revenue Nomad crawls the web for open fractional, interim, and contract go-to-market roles — fractional CROs, CMOs, RevOps leads, growth operators — scores each listing for relevance, and aggregates everything into a job board inside the **Operator Portal**.

## How it works

1. **Crawl** — source adapters pull from job boards *and* the places people talk about fractional GTM work:
   - **Job boards:** [Remotive](https://remotive.com), [RemoteOK](https://remoteok.com), [We Work Remotely](https://weworkremotely.com), [fractionaljobs.io](https://www.fractionaljobs.io), and any [Greenhouse](https://greenhouse.io) company board via `RN_GREENHOUSE_BOARDS`
   - **Communities:** [Hacker News](https://hn.algolia.com) stories *and* comments (catches "Ask HN: Who is hiring?" threads and founder chatter) and Reddit search — surfaced as **community leads**, distinct from listings on the board
1b. **Predict** — the operator's ICP is deduced from their Revenue Nomad profile (role, industries, stages, employee/revenue size, segment, sales motions) and cross-referenced against a universal company dataset (the open YC company directory) — target accounts are discovered automatically, then enriched with timing signals: actively hiring, early-stage GTM inflection, content gaps, careers-page GTM roles, funding news, and leader departures. No manual account list needed.
2. **Score & filter for truly fractional** — every item needs BOTH a relevance score above threshold AND a genuine fractional signal: fractional/interim/advisory wording, ≤4 days per week, ≤32 hours per week, or hourly-rate pricing. Full-time tells (benefits language, 40-hour weeks, annual salaries) subtract points, and full-time roles are dropped entirely. Commitment ("2 days/wk"), rate ("$150/hr"), and contract term ("6-month") are extracted as structured fields on each card.
3. **Aggregate** — matches are deduped (company + title), upserted into a JSON store (`data/jobs.json`), and stale listings age out after 60 days unless you've saved them.
4. **Operate** — the portal at `/portal` gives you search, filters (function, engagement type, source, score, remote), fit-score sorting, and a lightweight pipeline: save, mark applied, hide.

## Trading Post — the product

The site *is* Trading Post: `/` is the landing page, the login and the app (old `/table?k=` links redirect). Jigsaw for the fractional GTM community: every row is a fractional engagement — the company, the seat, and the people involved — and members **give** (add what's missing, verify what's right) to **get** (spend credits to unlock 🔒 fields).

- **Fill an empty field → +1 credit (up to 25 per rolling 24 hours). Unlock a 🔒 field someone else filled → 1 credit.** Starting balance: `RN_STARTER_CREDITS` (default 25, also set in `render.yaml` and the Dockerfile). When the starter balance goes down, anyone it would leave below 0 is lifted to 0 once, so nobody starts in debt. Invite bonuses (+10 each) and confirmation bonuses (+1) count toward the same 25; any part that doesn't fit is held and paid automatically as the rolling window frees room. New accounts can unlock 20 facts in their first 24 hours, then 100 a day.
- **Verify** any value you can see (once per person). Values show their confirmation count (✓n) even while locked; values from Revenue Nomad's own records count as one.
- **Report** a wrong value (members who have added a fact, up to 10 a day): it is hidden for the reporter at once and for everyone after a second member reports it, until an admin (`RN_ADMIN_EMAILS`) reviews; removal reverses the filler's credit and refunds unlockers.
- **Server settings**: `RN_ID_SECRET` keys the public engagement and person ids (their internal ids contain names; generated by Render). Rate limits read the client address from the rightmost `X-Forwarded-For` entry; set `RN_CLIENT_IP_HEADER` (e.g. `true-client-ip`) or `RN_TRUSTED_PROXY_HOPS` to match the host's proxy (`RN_LOG_IP_HEADERS=1` logs the candidate headers). `scripts/test-server.mjs` checks a running server end to end (`BASE=http://localhost:3000 STARTER=25 node scripts/test-server.mjs`, against a server on a fresh data dir started with `RN_SCAN_TEST=1 RN_CRON_SECRET=qa-cron`, which lets the tests store scan results without reading a job board; never set `RN_SCAN_TEST` in production). Three more checks need no server: `npx tsx scripts/test-scan.mts` (the open-role collector and the weekly email's wording, no network), `npx tsx scripts/test-digest.ts` (the weekly email run with a stubbed sender) and `npx tsx scripts/test-model.mts` (the app's filters, free and locked lists and role dates).
- **What a member sees first.** One next-move card at the top of the table: fill in your seats, then new open roles in your function this week, then low credits. It never shows with Get started, whose second step reads "Fill in your seats" for a member with seats on file. Dismissing a card hides that kind for 7 days.
- **Free and locked.** Free: company facts, function, type, start, why hired, pricing model, hours per week, revenue and employees at the time, a person's title and relationship, and the status and dates of a role the scan follows. Locked (1 credit each): role, status, seat holder, end, how sourced, rate, posting, and a person's name, email, phone and LinkedIn.
- **Your seats.** The member a seat holder name resolves to sees every fact on their own seat free (`EngagementRec.yours`), can correct what Revenue Nomad's records or the scan say about it (no credit for a correction), and can say "This isn't me" (`notMine`) to unlink a wrong name match. People on the seat stay locked. The **Your seats** page (account menu) lists those seats with every missing fact answered in place: pick lists save in one tap, a rate goes on the record or to the benchmarks only, and "Add a seat we don't have" adds one the member held. Each fact earns 1 credit inside the daily 25.
- **Rate benchmarks** group by function and client revenue band. Points come from rates on records, rates members share for the benchmarks only (`benchRate`: +1 credit, counted in the medians, never shown to anyone, left out of the admin export's member data), and Revenue Nomad's Rate Index (`rateIndex` in the seed). A group shows numbers at 5 rates, or at 20 when it includes Rate Index data. The Rate Index points are anonymous (function, hourly rate, hours a month, client revenue band): `node scripts/add-rate-index.mjs` reads the git-ignored `data/rate-index.private.json` into the private seed, `scripts/build-intel-seed.py` carries them over on a rebuild, and `scripts/seal-intel-seed.mjs` re-seals the seed afterward.
- **Weekly scan.** Open fractional GTM roles come in with the day they were first seen; a role closes (status `Closed`, with the date) once a clean scan of its board hasn't listed it for 10 days, and reopens if it is listed again. An open role hides its company; closing shows it again. Naming the seat holder on an open role fills it. Turn it on with `RN_SCAN=1` (a scan starts in the background when the last one is over 7 days old), or point a weekly cron at `POST /api/table/scan` with the header `x-cron-secret: $RN_CRON_SECRET` (the endpoint is off without `RN_CRON_SECRET`). Admins can also start one from the app (`scanNow`, the "Run scan now" button on Pilot metrics). The scan reads fractionaljobs.io, Remotive, RemoteOK, We Work Remotely and the Greenhouse boards in `RN_GREENHOUSE_BOARDS` (`lib/scan/collect.ts`): listings only, GTM seats only, a real named company, posted in the last 60 days, at most 60 roles a run. A board that fails is listed with its error on Pilot metrics and closes nothing. In the app, a followed role reads "Open since Nov 3" or "Role closed Dec 8 · listed 35 days", the Open roles filter has "Open now" and "Closed", and Hiring now says when the last scan ran. Run one scan on the host after the first deploy and read the per-source table: the collector has only been checked against saved pages, not the live boards.
- **Weekly email.** After a scan that found new roles, each member who has signed in gets the week's new open roles, unless they turned it off (`RN_DIGEST_ALL=1` sends it to every member on file with an email, signed in or not). It only sends when email is set up (`RESEND_API_KEY`, `RN_EMAIL_FROM`) and `RN_PUBLIC_URL` is set; `RN_DIGEST=0` keeps it off. Every email carries an unsubscribe link (`GET /api/table/unsubscribe`), and members can switch it in My credits (`settings`). The switch shows only while the weekly email is on for the server (`View.scan.digest`). `RN_EMAIL_FOOTER` is the postal address line printed in the footer when set.
- **Pilot metrics** (admins, `View.admin`): members active in the last 7 and 30 days, credits at zero, how often members ran out of credits on an unlock, Pro waitlist interest and where it came from, the most unlocked and most added fields, scan and email health. It is in the account menu for admins, with "Download backup".
- **Pro waitlist.** The pilot is free. Where members run out (the zero-credits popover, a hidden company's record, My credits, the foot of Hiring now) a "Pro is coming" offer asks who wants more, with no price. The app records each view, each "Tell me when it's ready" and each tap on a lock at 0 credits (`signal`), and Pilot metrics reports them.
- **Add record** starts from the company URL: the server reads the site for the name and a suggested Revenue Nomad industry tag; the member sets revenue stage and employee count (Revenue Nomad pick lists, as they were at the time), the engagement, and the people (Reported to / Reported to me / Worked with). Everything is editable. **+ person** adds someone to any record.
- **Join** from the landing page with name + email (new people). Revenue Nomad members sign in with their personal link (or its code); a member's email can't be claimed by joining.
- Every row shows the company's icon (website favicon, else a background name lookup, else initials).
- **Source** column/filter: *Published engagement*, *Member success story*, *Demand scan*, *Member added*.

Companies, engagements and contacts are linked entities (company 1→n engagements 1→n contacts): company data is entered and unlocked once for every row at that company. Fields and Revenue Nomad pick lists live in `lib/tableFields.ts`.

**Data.** `scripts/build-intel-seed.py` aggregates Revenue Nomad's own data: published engagements (admin portal export), every company named in Talent Signup success stories (the member's words become the record's context), Fractional GTM Demand Scan exports (`--demand`), and verified websites (`--domains`). It also writes one private sign-in link per member.

```bash
python3 scripts/build-intel-seed.py Talent_Signups.csv engagements.csv --demand demand-scan.csv --domains domains.json
node scripts/seal-intel-seed.mjs     # encrypts it to data/intel-seed.enc (key in data/intel-seed.key)
```

Member data never goes into git in the clear (this repo is public): `data/intel-seed.json`, `data/intel-member-links.csv`, `data/intel-seed.key` and runtime state are git-ignored. Hosts get the AES-256-GCM encrypted `data/intel-seed.enc` with the code and open it with `RN_INTEL_SEED_KEY` (the contents of `data/intel-seed.key`). Use persistent storage for `RN_DATA_DIR` (Railway volume / Render disk / Docker volume). With no seed, the page runs on labeled demo data (`/?k=demo`).

The job-board crawler and prospect engine remain back-end services only (`/api/crawl`, `/api/jobs`, `/api/prospects`) — future scheduled enrichment for Trading Post, not part of the UI.

## Launch / Deploy

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fmjmlopez1-beep%2FRevenue-Nomad-)
[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fmjmlopez1-beep%2FRevenue-Nomad-)

Pick whichever fits:

- **Vercel (fastest)** — click the button above, accept defaults, done. `vercel.json` schedules a daily crawl at 06:00 UTC automatically. Note: Vercel's filesystem is ephemeral, so the job database lives in `/tmp` and resets on cold starts — each crawl fully repopulates it, so the board stays fresh, but saved/applied state may not persist. Fine for a public board; set `CRON_SECRET` to protect the cron endpoint.
- **Render (persistent)** — click the button above; `render.yaml` provisions the web service plus a 1 GB persistent disk at `/var/data`, so operator state (saved/applied/hidden) survives restarts.
- **Docker (any host: Railway, Fly.io, a VPS)** — `docker build -t revenue-nomad . && docker run -p 3000:3000 -v rn-data:/data revenue-nomad`. The image is a self-contained standalone build; mount a volume at `/data` to persist the job database.

**Keeping the board fresh:** besides Vercel Cron, the repo ships a GitHub Actions workflow (`.github/workflows/crawl.yml`) that pings `POST {CRAWL_URL}/api/crawl` daily — set the repository variable `CRAWL_URL` to your deployed URL (and secret `CRON_SECRET` if you configured one). CI (`ci.yml`) builds every push.

## Getting started

```bash
npm install
npm run dev        # http://localhost:3000
```

The board ships with clearly-labeled sample listings so the UI works immediately. Click **Run crawl** in the portal (or run `npm run crawl` from the CLI) to replace them with live roles.

> Note: crawling makes outbound HTTPS requests to the job sources above, so it needs normal internet access. Each source fails independently — one being down never blocks the others.

## API

- `GET /api/jobs` — list jobs. Query params: `q`, `function`, `engagement`, `source`, `status`, `minScore`, `remote=true`
- `POST /api/crawl` — run a crawl and upsert results
- `PATCH /api/jobs/:id` — body `{ "status": "new" | "saved" | "applied" | "hidden" }`

## Configuration

See `.env.example`:

- `RN_GREENHOUSE_BOARDS` — comma-separated Greenhouse board tokens to watch specific companies
- `RN_DATA_DIR` — where the JSON job database lives (defaults to `./data`)
- `RN_STARTER_CREDITS` (default 25), `RN_ADMIN_EMAILS`: Trading Post credits and admins
- `RN_SCAN=1` or `RN_CRON_SECRET`: the weekly scan of open roles (see Weekly scan above)
- `RESEND_API_KEY`, `RN_EMAIL_FROM`, `RN_PUBLIC_URL`, `RN_DIGEST`, `RN_DIGEST_ALL`, `RN_EMAIL_FOOTER`: sign-in emails and the weekly email

## Scheduling crawls

Any scheduler that can hit `POST /api/crawl` (or run `npm run crawl`) works — a cron job, a Vercel/Netlify scheduled function, or GitHub Actions. Hourly-to-daily is plenty for these sources.
